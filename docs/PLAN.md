### M9 part 2 delivered: browser HAR capture (`wstg capture`)
- `src/wstg/capture.py` + `wstg capture TARGET [--role NAME] [--url URL] [--headless]`: drives a headful Chromium (Playwright) on the Kali host so the tester logs in and walks the target by hand (no login automation, owner's choice); the session is recorded to a HAR and the context's storage state (cookies, localStorage, sessionStorage) is saved, both stored as a new `har-browse` version via the existing evidence Store (`items/*.har`, read by `wstg-har` and the wired WSTG steps). Replaces the manual "Preserve log → Save all as HAR → upload" steps; login/navigation stay manual.
- Scope-enforced: an FQDN target only (a domain target is passive); the scope record must be authorized and valid; the start URL's host and port must be in scope. Hosts contacted during the session are recorded and the result reports any out-of-scope hosts (not blocked, so third-party resources still load — the tester is responsible, as with Burp). The HAR and storage state hold real secrets, so they stay in the evidence folder and never enter a finding or the AI prompt (prompt excludes HAR; `wstg-har` prints no values).
- Launch model (owner chose CLI): the browser window opens on the host that runs the command, so the tester works on the Kali desktop (or VNC). A web-UI button was declined to avoid launching a GUI browser from the loopback web service.
- Dependency: `playwright>=1.49` added; `setup-kali.sh` installs the browser (`playwright install --with-deps chromium`, or just `chromium` under `--no-packages`). Playwright is imported lazily inside the driver, so the rest of the app and the tests run without it.
- `tests/test_capture.py` uses a fake browser driver (no real Chromium): stores HAR + storage state as `har-browse`, flags out-of-scope hosts, and refuses a domain target, an unauthorized scope, an out-of-scope start URL, and an empty recording. Full suite 259 passed.
- HAR acquisition unified on `wstg capture`: the shared `har-browse` evidence description (catalog/evidence/core.yaml) now prefers `wstg capture {fqdn} --role ROLE`, with the F12 / "Save all as HAR" flow as a fallback, so every HAR-using test (SESS, CRYP, INFO...) gets the new capture method in one place. ATHN-01 step 3 records with it; SESS-02 step 3 points at it.
- Session fixation (WSTG-SESS-03) reuses the login HAR (no separate capture): the new auto evidence `session-reissue` runs `wstg-sess` (`src/wstg/sessionscan.py`, stdlib) which reads `har-browse` (inputs: [har-browse]), finds the login POST (a password field in the body), reads the session identifier before and after login and decides whether it is reissued, scans the request URLs for a session id (URL-based fixation), and - best effort - replays the pre-login cookie against an authenticated URL on the target to check whether the old identifier is still accepted. The pure analysis (`src/wstg/session.py`: session-cookie detection, reissue rows, URL detection, logged-out heuristic, value masking, HAR reading) is unit-tested; the replay runs against a loopback server. Identifier values are masked so the raw ones stay in the HAR only. The one operation (log in during the browser capture) is shared with every other HAR-using test. The earlier interactive `wstg capture-fixation` command was dropped in favour of this. The login is found from a password field in the request body, including localised names (senha, contraseña, mot de passe, …) and nested-JSON or urlencoded bodies; when no login request can be located it falls back to the first/last value of each session cookie and reports the result as inconclusive (not a failed collection) rather than exiting non-zero, so a non-English or token-based login still yields usable evidence. SESS-03 steps: compare from the login HAR (step 1, auto), privilege-change reissue by hand (step 2, `session-reissue-tests` now just that), AI judge (step 3). The active injection test is not automated; a not-reissued identifier already fails, which covers the common case.
- Value leaks removed while integrating `wstg-har`: CRYP-02 step 1 and CRYP-04 steps 1-2 printed logged-in cookie/URL values from the HAR with jq; they now enumerate the candidate names value-free with `wstg-har cookies`/`urls` and the tester decodes the specific values by hand. CRYP-03 was already switched in part 1. The CRYP-02 prompt test still confirms no HAR value reaches the AI prompt.
- Deferred/next: scripted login automation (declined for now); an optional web-UI trigger if the operation model changes.

## Architecture

### Storage split
- **SQLite** (outside the repo): users, targets, scope records, per-step verdicts, findings, evidence index (relative path, SHA-256, collected date, version), jobs.
- **Evidence files** (outside the repo): `<evidence_dir>/<target>/<evidence_id>/<version>/...`
  - Each collection or edit creates a new version folder. Originals are never overwritten.
  - A version folder is written to a temp path and renamed when complete.
- **Catalog** (in the repo, YAML, English):
  - `catalog/evidence/*.yaml`: evidence definitions. ID, target type (`domain` / `fqdn`), `auto` / `manual`, level (`light` / `full`), command, output files, load note.
  - `catalog/wstg/WSTG-*.yaml`: per-WSTG scenario. Overview, pass/fail criteria, steps (summary, command or concrete operation, referenced evidence IDs).
  - Evidence is defined once and referenced by several WSTG scenarios. This replaces the predecessor's commands embedded in step text.

### WSTG status
- `-`: no step verdict and no evidence
- `started`: at least one step verdict or evidence
- `fail`: at least one step is `fail`
- `pass`: every step is judged as `pass` or `no need`, with at least one `pass`
- `no need`: every step is `no need`
- Step verdicts are `pass`, `fail`, or `no need` (migration `0012_step_no_need`): `no need` marks a step that does not apply to this target (e.g. an optional PoC confirmation), so an overall pass/fail can be reached without that step passing. The tester can still override the whole-test status (see the tester-annotations section).

### Runtime
- Flask app on 127.0.0.1, behind nginx on **HTTP port 8083** with `allow 192.168.0.0/16; deny all;`.
  - Later, when the tool is opened to everyone: DNS name, TLS certificate, port 443.
- A separate worker process runs queued jobs (automatic evidence) from a SQLite table.
- Both run as systemd user services on Kali.

### Scope
- Each target has a **scope record**: allowed hosts and ports, authorization reference, validity period.
- Every command is checked against the scope before it runs. Out of scope or expired → refused.
- Domain targets run passive commands only (DNS, whois, CT logs, search engines).

### Traffic capture (replacing the Burp history checks)
- No Burp dependency. Use Python HTTP libraries and curl.
  - Unauthenticated crawl and per-request checks (headers, cookies, methods, redirects, error pages): Python HTTP client + curl.
  - Login flows and JavaScript-heavy pages: a headless browser driven from Python, recording a HAR.
  - Manual browsing by the tester: HAR exported from the browser and imported (manual evidence), parsed automatically.
- ngrep only sees plaintext HTTP, so it is not used for HTTPS targets.
- Details are settled in M9.

- WSTG-CRYP-02 (padding oracle) step 3 automated as a safe three-case probe; padbuster (step 4) stays manual. New console script `wstg-cryp padding-probe` (`src/wstg/cryp.py`) and the former manual evidence `padding-oracle-responses` promoted to auto (level full, inputs http-root-https, har-browse, session-token-samples). It gathers encrypted-looking values itself (anonymous Set-Cookie and hidden form fields from http-root-https, extra cookie samples from session-token-samples, logged-in session cookies from the har-browse storage state, and URL query values from the HAR), keeping only those that decode (hex, standard/urlsafe base64, or .NET UrlToken) to at least one block, a multiple of 8/16 bytes, and not readable plaintext. For each it sends three versions back - original, last byte of the last block flipped (bad padding), first byte of the second-to-last block flipped (content garbled, padding still valid) - re-encoded in the same codec and injected in the same channel (cookie header, query parameter, or a form POST), replaying the logged-in session for har-browse candidates. It reports the median status, length, and time of each case over `--repeat` requests and flags SUSPECTED-ORACLE when bad-padding differs from garbled-content (status or length; a large timing gap is reported as TIMING-DIFF to confirm by hand). No decryption is attempted, only the base host is contacted, and token values are never printed (name, codec, decoded length only). Step 3 became an `auto_run` `cat {ev:padding-oracle-responses}/stdout.txt` with a manual fallback for a value only reachable deep in a logged-in flow; padbuster now records to a new manual evidence `padding-oracle-confirm`, run only on a flagged candidate by agreement. `tests/test_cryp.py`: codec round-trips, candidate detection (plaintext/short rejected, 16-byte multiple preferred), mutation (padding broken vs kept), and a loopback PKCS#7 oracle (leaky -> SUSPECTED-ORACLE, constant -> no signal, no candidate -> recorded). - WSTG-BUSL-04 (process timing) step 1 split into a tool-assisted timing measurement and a manual race step. New console script `wstg-timing diff` (`src/wstg/timing.py`): the tester names a request, the parameter, and two values (class A / class B) that pick the outcomes to compare (success vs failure, exists vs absent); the tool sends the two classes interleaved (A, B, A, B, ...) to cancel clock drift and load trends, discards warm-up requests, and reports per class the median and IQR of the round-trip time, the median response size, and the status codes. A two-sided Mann-Whitney U test (standard library, no SciPy - rank sums with tie correction and a normal approximation) gives the verdict: STATUS-DIFFERS (a direct state oracle), DISTINGUISHABLE (significant p < 0.01 and a median gap above measurement noise; a large size gap is flagged as a possible transfer-time confound), NOT-DISTINGUISHABLE, or INCONCLUSIVE. GET by default (--method POST --body for a form POST), --fixed NAME=VALUE for constant parameters, --har reuses a logged-in session; only the base host is contacted and the two compared values are not printed (class A / class B, length only). Dependency: none new (standard library). Left manual, unchanged: BUSL-04 race exploitation, the rest of BUSL-01..09.

- Resumable ffuf (owner request: keep the results as it goes and continue from there after a failure). New tool `wstg-ffuf-run --resume DIR [--chunk N] -- ffuf ARGS` (`src/wstg/ffufrun.py`): splits the `-w` word list into chunks of 100 words and runs ffuf once per chunk with `-o DIR/chunk-NNNN.json` (written as .part, renamed only when ffuf exits 0 and the JSON reads back); the next run skips the done chunks; when all are done they are merged into the `-o` file in ffuf's JSON format (results, config, original command line, `chunks`), so `wstg-ffuf` and the jq commands read it as before. DIR is reused only for the same scan: key.txt holds a hash of the word list and of the result-changing arguments (-o, -p, -t, -x, -rate, -s, ... left out, so changing WSTG_PAUSE or the proxy keeps the done chunks). New argv placeholder `{resume}` = `<evidence>/<target>/<id>/.resume` (kept between runs, removed by the runner once a version is stored complete; refused with `direct`). content-ffuf, backup-ffuf and vhost-ffuf use it. A stopped run loses at most one chunk (backup-ffuf: 700 requests, about 13 minutes at WSTG_PAUSE 1); each chunk repeats ffuf's -ac calibration (a few extra requests). The failed version still says failed; collect again to continue. Tests: `tests/test_ffufrun.py` (fake ffuf: merge, resume after a failed chunk, pacing change keeps chunks, other extensions start again, usage errors, runner keeps .resume until complete).
