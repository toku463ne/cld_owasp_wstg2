Tools › Raw request probe

WSTG-INPV-16 step 2. For each path the front end should block, it sends path-normalisation variants (case, trailing dot/slash, dot segments, an encoded separator, a semicolon parameter) and flags a front-end bypass when the canonical path is blocked (401/403/404) but a variant is not — the front and back end normalised it apart. It also sends a small parser battery to / (a duplicate Host, a duplicate Content-Length, bare-LF line endings, an unrelated Host, an unknown method) and flags a precondition that is accepted. Candidate paths come from katana-crawl and from the owner's blocked paths you type below. It sends raw/malformed requests (a WAF may flag them), so run it by agreement; the WSTG-INPV-16 judge decides against the owner's front-end config (a blocked variant is a pass).
